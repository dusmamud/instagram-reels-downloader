# Security Policy

## Supported versions
Only the latest release on `main` is actively supported with security fixes.

| Version | Supported |
| ------- | --------- |
| 1.0.x   | Yes       |

## Reporting a vulnerability
Do not open a public issue for a security vulnerability. Use GitHub
Security Advisories (Report a vulnerability on the repo's Security tab)
if available, so the details stay private until a fix is ready.

Include, where possible:
- What the vulnerability is and where it lives (file / function)
- Steps to reproduce (without real credentials, cookies, or private URLs)
- The impact you think it has

You should get an acknowledgement, and a fix or a plan will be shared
before any public disclosure where that is possible.

## What not to report here
- Instagram changing its site and breaking downloads: that is a bug,
  not a security issue — open a normal bug report instead.
- A reel you do not own being downloadable: that is a content /
  copyright question, see DISCLAIMER.md.

## Safe use notes
- Never share your `cookies.txt` file or browser profile. It can give
  access to your Instagram account.
- Only run cookies modes on a machine you trust, and prefer Firefox
  cookies or a fresh export over sharing a full browser profile.
